How a judge model spends 100 points on a Laravel codebase

Behavioural tests say whether the app works. This scorecard says whether the code is worth keeping — eight dimensions, forty-nine criteria, every deduction pinned to a file:line.

STEP 1

A model gets the phase-1 spec and a fixed Laravel starter. It writes the catalog, roles, search, deactivation — and its own tests.

STEP 2

The harness runs the gates and records them: Pint, PHPStan, the test suite, composer test, plus five hidden behavioural probes.

STEP 3

A blinded judge gets only the diff plus that evidence packet. No model name, no other submission, no ranking.

STEP 4

The judge fills a worksheet: one score per criterion, a deduction ledger so one flaw is charged exactly once, and citations for every point withheld.

Duplication, dead code & clarity
